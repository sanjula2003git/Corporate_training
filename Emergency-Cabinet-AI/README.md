# 🧰 One Door Opens — an Intelligent Emergency Cabinet

An emergency cabinet has seven locked compartments. This project builds the part that decides
which ones to unlock, using what is known about the emergency and what is left in the cabinet.

The other emergency projects in this repo stop at *classify the emergency*. This one goes
further: the cabinet has to make a **safe inventory decision while it is still unsure** — which
doors to open, which to keep shut, and when to stop and ask a person.

## ⚠️ This is a teaching simulation

Every emergency, every shelf and every sensor reading is generated by code in the notebook. No
real cabinet, no real patient, no real call. A real version of this would be medical equipment
and would have to be approved by the people whose job that is.

## The rule the whole project is built around

```
approved protocol / dispatcher  ->  list of equipment allowed for this incident
   ->  the AI picks from that list  ->  fixed safety checks
   ->  the compartment unlocks      ->  sensors check what actually happened
```

**The AI never decides what treatment anybody needs.** It chooses *which supplies to hand over*,
from a list it was given, and the fixed checks always get the last word. Nothing in this project
decides anything about a shock — that belongs to the AED.

## What is in the folder

| File | What it is |
|---|---|
| `One_Door_Opens_Emergency_Cabinet.ipynb` | the notebook, 99 cells, runs top to bottom in Colab |
| `build_nb.py` | builds that notebook — **edit this, not the `.ipynb`** |
| `story.py` | the cabinet, the models and the figures, for the app |
| `bridge.py` | the teaching registry: 15 steps, five parts each |
| `app.py` | the illustration app, one page per step, routed by `?stage=` |

Rebuild the notebook with:

```
py -3.13 -X utf8 build_nb.py
```

The `-X utf8` matters on Windows: without it every em-dash in the prose is mangled.

Run the app with:

```
py -3.13 -m streamlit run app.py
```

Navigation inside the app is by button, never by markdown link — Streamlit renders every markdown
link with `target="_blank"`, so a link opens a new browser tab on every click.

## The teaching arc

1. A person tries it by hand, and takes what was said out loud rather than what is needed
2. The inventory, as dictionaries and then as a table
3. Emergencies, generated as **truth first and then a damaged report** of that truth
4. The rule-based cabinet — the honest baseline
5. Seven awkward calls that break it
6. A multi-label model, because almost no emergency needs only one compartment
7. The fixed safety checks, which can only ever take things away
8. A cost function, and all 128 possible kits
9. A whole day across five cabinets, at four stock levels
10. The sensor event log
11. Misuse and broken sensors — plain rules against an isolation forest
12. The whole cabinet behind seven doors, with `ipywidgets`

## Results (simulated, and computed rather than chosen)

Scored on the same 1200 unseen emergencies, all seven compartments:

| System | Missed items | Extra items | Got everything needed |
|---|---|---|---|
| Rules | 255 | 89 | 80% |
| Logistic regression | 148 | 54 | 88% |
| Random forest | 151 | 52 | 88% |
| Decision tree | 186 | 112 | 86% |

**The example call resolves exactly as the brief asked**, and from the cost function rather than
from a hardcoded answer: *"a cyclist has fallen, there is bleeding, but I don't know how serious
it is"* → protective equipment, bleeding supplies, traffic markers and the communication unit
open; AED, burn supplies and flotation stay shut.

## Four things worth knowing before you teach it

**The rules are not bad — they are helpless about uncertainty.** On the compartments the caller
reports reliably, the plain rulebook is perfect and no model beats it. Every bit of the model's
gain is in the compartments where something was *left out* of the report. And on the one field we
damaged by flipping it at random, the model is no better at all: missing information can often be
worked out from context, wrong information cannot be recovered by anybody.

**Two compartments do not get a model.** Protective equipment and the communication unit are
needed in every single emergency, so there is nothing to predict — a per-label classifier trained
on them sees only one class and crashes. They are a rule instead, written where people can see
it.

**"Not every door costs the same to open" is what makes the cabinet cautious.** The first version
priced a spare pair of gloves the same as the cabinet's only defibrillator, so it opened the AED
on a 12% chance. Giving each compartment its own cost-of-being-wrong produces the wanted
behaviour — gloves open above 4%, the AED above 39% — without a single rule saying so.

**The clever strategy only wins in the middle.** Run the day at four stock levels and the
smallest-sufficient-kit strategy ties the rulebook on full shelves, beats it when supplies are
tight, and loses slightly when they are nearly gone. That is a narrower claim than "the AI wins",
and it is the one the numbers support.

**And the isolation forest loses to four `if` statements.** It flags 2 of 4 faults; the rules
catch 4 of 4. This is kept in the notebook rather than tidied away, with the reason: an isolation
forest splits *inside the range of values it has seen*, so "the same thing but much more of it" —
which is most of what breaks a cabinet — is exactly what it is worst at.

## Editing notes

Three traps this build hit, all of which the code now guards against:

- **`what_is_allowed` must not filter on the dispatcher.** If unconfirmed restricted items are
  removed before the optimiser runs, the `waiting` state becomes unreachable and the cabinet can
  only ever say "not needed for this emergency".
- **`cabinet_decides` also computes what it *would* have asked for with full shelves.** Without
  that second call, a compartment that is needed but empty reports "not needed", which is a very
  different and much more misleading statement.
- **The future-shortage penalty applies only to consumables.** Charging it on a borrowed
  defibrillator costs ~17 points to open a device that comes straight back, and suppresses the
  AED almost entirely.

All results are verified by executing every cell and by rendering every figure to PNG and looking
at it. The notebook takes about 90 seconds to run.
